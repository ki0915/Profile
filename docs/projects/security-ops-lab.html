보안 운영 랩: 월간 점검 자동화와 디스크 장애 재현

KISA Unix 점검 항목을 지난달 결과와 비교해 조치 이행을 추적하는 월간 점검 스크립트와, 호텔 서버 디스크 고갈 장애를 1GiB 디스크로 재현해 만든 Docker 정리 가드입니다.

개인 랩(AI 협업)이며 저장소는 공개하지 않았습니다.

요약

KISA Unix 계정과 권한 점검 결과를 지난달과 비교해, 미조치 항목이 며칠째 남아 있는지 보여 주는 seccheck를 만들었습니다. 실무에서 겪은 Docker 디스크 고갈 장애도 1GiB 디스크로 재현했습니다. 정리 없이 배포하면 14번 중 7번 실패했고, 롤백 이미지를 지키는 단계형 정리 가드를 붙이자 14번 모두 성공했습니다.

배경

점검 표준을 문서로 남기는 것만으로는 지적된 항목이 실제로 고쳐졌는지 알기 어렵습니다. 지난달 결과와 이번 달 결과를 나란히 놓고 봐야 미조치 항목이 드러납니다.

호텔 서버에서 겪은 디스크 고갈 장애는 cron 정리로 막았습니다. 퇴사 뒤에는 롤백용 이미지는 지키면서 디스크 사용률에 따라 단계적으로 정리하는 방식을 랩에서 다시 만들어 봤습니다.

한 일

seccheck: 월간 점검과 이행 추적

KISA 가이드의 Unix 계정과 권한 항목 10개(U-01, 02, 03, 04, 07, 08, 15, 44, 47, 48)를 점검하고, 로그인 실패가 몰린 IP와 허용 목록 밖에서 열린 포트도 확인합니다. 읽기만 하고 설정은 바꾸지 않습니다. 지난달 결과를 함께 넘기면 항목마다 신규, 미조치, 조치 완료로 나누고 미조치 경과일을 셉니다.

양호 7 · 취약 3 · 해당 없음 2  |  신규 0 · 미조치 3 · 조치 완료 2

U-02  패스워드 복잡성 설정      상  FAIL  미조치     31일  pwquality.conf 없음
U-03  계정 잠금 임계값 설정     상  FAIL  미조치     31일  faillock deny 미설정
U-47  패스워드 최대 사용기간    중  PASS  조치 완료        PASS_MAX_DAYS=90
U-48  패스워드 최소 사용기간    중  PASS  조치 완료        PASS_MIN_DAYS=1

두 번째 실행은 날짜 인자로 한 달 뒤를 가정해 같은 VM에서 돌린 시연입니다. 단위 테스트 4건이 있습니다.

disk-guard: 단계형 Docker 정리

  • 사용 중인 이미지, 보존 라벨이 붙은 이미지, 롤백용 최신 이미지는 지우지 않습니다.
  • 디스크 사용률이 70% 이상이면 오래된 태그를, 85% 이상이면 중지된 컨테이너와 빌드 캐시 전체를 정리합니다.
  • 컨테이너 로그는 사고 때 증거가 되므로 지우지 않고 경보만 냅니다.
  • 기본 동작은 dry-run이고, flock으로 동시 실행을 막습니다. 지운 내용은 JSON 감사 로그와 Prometheus 지표로 남기고 경보 규칙을 붙였습니다.

재현 실험

별도 dockerd를 1GiB 디스크 위에 띄우고, 40MB 레이어를 가진 이미지를 14번 배포했습니다. 3번째 버전에는 보존 라벨을 붙이고 4번째 버전은 롤백 대기 컨테이너가 참조하게 해서, 정리 도구가 이 둘을 지우지 않는지도 확인했습니다.

실험하면서 틀렸던 것

처음에는 이미지를 지우면 디스크 사용량이 줄 거라고 생각했는데 줄지 않았습니다. BuildKit 빌드 캐시가 같은 레이어를 붙잡고 있었습니다. 캐시 상한을 넣자 사용률이 91%에서 38%로 내려갔습니다.

정리를 배포 전에 돌리면 최고점이 낮아질 거라는 예상도 측정해 보니 틀렸습니다. 최고점은 지켜야 하는 이미지들의 크기로 정해졌습니다.

개인 실험 결과이며 실서비스 수치가 아닙니다. 시나리오와 판단은 제가 맡았고 구현은 AI와 함께 했으며, 실행과 결과 검토는 직접 했습니다.
