ETK-Scanner

비용 상한이 있는 LLM 기반 소스코드 취약점 진단(SAST)

정적분석으로 후보를 좁히고 LLM 검증은 필요한 곳에만 쓰는 소스코드 취약점 스캐너입니다. 결과를 SARIF 2.1.0으로 내보내 GitHub Actions에 붙였습니다.

저장소 github.com/ki0915/etk-scanner

요약

함수마다 비싼 LLM을 부르면 비용이 너무 크고, 정적분석만으로는 권한 우회 같은 로직 결함을 놓칩니다. 그래서 Python AST와 JS/TS 패턴으로 후보를 좁힌 뒤 저비용 모델, 고비용 모델 순으로 검증하고 예산 상한 전에 멈추는 스캐너를 만들어 SARIF 2.1.0으로 GitHub Actions에 연결했습니다. 이 스캐너를 활용해 오픈소스의 인가 처리 문제를 제보했고, 유지관리자에게서 영향이 있다는 확인과 함께 고치겠다는 답을 받았습니다.

배경

비용 대비 효율이 좋은 취약점 진단 도구를 만들고 싶었습니다. 위험 함수(eval, exec) 호출만 찾는 규칙 기반 도구는 권한 우회나 검증 우회처럼 위험 함수 없이 생기는 결함을 잡지 못합니다. 반대로 모든 함수를 LLM에 보내면 비용 때문에 CI에 붙일 수가 없습니다.

한 일

단계형 파이프라인

정적 탐지
Python은 AST로, JavaScript와 TypeScript는 정규식으로 후보를 뽑습니다. 이 단계는 토큰을 쓰지 않습니다.
단일턴 분류
저비용 모델이 후보를 한 번 거릅니다.
멀티턴 검증
남은 소수만 고비용 모델이 여러 차례 문맥을 확인하며 검증합니다.
보안 영향 필터
기능 버그와 보안 결함을 나누고, LLM의 분류와 실제로 악용할 수 있는지를 구분해 표시합니다.
기록과 출력
모든 API 호출 비용을 cost.json에 기록하고, 설정한 예산을 넘길 것 같으면 그 전에 멈춥니다.

후보를 고를 때는 위험 함수만 보지 않고, validate나 auth처럼 보안 판단을 하는 함수를 함께 잡습니다. 권한 우회나 검증 우회는 위험 함수 호출 없이도 생기기 때문입니다.

CI 연동

탐지 결과의 CWE, 심각도, 파일과 행 위치를 SARIF 2.1.0으로 변환해 GitHub Security 탭에 올립니다. GitHub Actions에서는 PR과 push마다 토큰을 쓰지 않는 정적 모드만 돌고, LLM 모드는 수동으로 실행합니다. 검사 뒤 SARIF를 업로드하고, 심각도 high 결과가 나오면 GitHub Actions job이 실패하는 게이트를 두었습니다.

하드코딩된 JWT 키 재현

직접 만든 TypeScript 실습 백엔드를 검사하자 정적 단계에서 소스에 박힌 JWT 서명 키(CWE-798)가 잡혔습니다. 이 키를 알면 누구나 토큰을 위조할 수 있습니다. 재현 환경에 실제 HTTP 서버를 띄우고, 키를 환경변수로 옮기기 전과 후를 비교했습니다.

오픈소스 인가 결함 제보

이 스캐너를 활용해 한 오픈소스 프로젝트의 인가 처리 문제를 소스 수준에서 분석하고, 재현 자료와 원인 분석을 유지관리자에게 보냈습니다. 특정 버전에 영향이 있고 그 버전에서 수정할 예정이라는 회신을 받았습니다. 아직 공개 전이라 프로젝트 이름과 세부 내용은 적지 않습니다.

CI job을 실패시키는 설정까지 했고, 보호 브랜치 규칙으로 실제 병합을 막는 설정은 확인하지 않았습니다. 제보 건은 유지관리자의 영향 확인과 수정 예정 회신까지이며, 패치 배포나 CVE 발급, 공개 발견자 등재는 아직 확인되지 않았습니다.
