소개

정적분석으로 의심 구간을 먼저 좁히고 LLM 검증은 필요한 곳에만 쓰는 취약점 스캐너를 만들어, 실습 백엔드와 오픈소스의 권한 문제를 찾았습니다.

위험 함수 호출만 찾는 규칙 기반 도구는 권한 우회나 검증 우회처럼 위험 함수 없이 생기는 결함을 잡지 못합니다. 모든 함수를 LLM에 보내면 비용 때문에 CI에 붙이기 어렵습니다. 비용 대비 효율이 좋은 취약점 진단 도구를 만들고자 시작했습니다.

처리 흐름

  1. 후보 좁히기 정적분석으로 보안 판단 함수와 위험 지점을 후보로 뽑습니다. LLM 비용이 들지 않습니다
  2. 저비용 분류 저비용 모델이 후보마다 한 번 분류합니다
  3. 고비용 검증 남은 소수 후보만 고비용 모델이 문맥을 여러 번 확인합니다
  4. 비용 회계 호출마다 비용을 기록하고 예산에 닿으면 멈춥니다
  5. 보고 SARIF로 GitHub 보안 탭과 CI job 결과에 연결합니다

구현

비용이 적은 단계부터 거르도록 정적분석, 저비용 모델 분류, 고비용 모델 검증 순서로 나눴습니다.

후보에는 eval 같은 위험 함수와 함께 validate나 auth처럼 보안 판단을 하는 함수를 넣었습니다. 권한 우회나 검증 우회는 위험 함수 호출 없이도 생기기 때문입니다.

  • Python 코드는 AST로, JavaScript와 TypeScript는 정규식으로 보안 판단 함수를 후보로 뽑습니다. 이 단계는 LLM 비용이 들지 않습니다.
  • 저비용 모델이 후보마다 한 번 분류하고, 남은 소수만 고비용 모델이 여러 차례 문맥을 확인하며 검증합니다.
  • 모든 LLM 호출의 비용을 기록하고, 정한 예산에 닿으면 분석을 멈춥니다.
  • 결과를 SARIF로 내보내 GitHub 보안 탭에 올리고, GitHub Actions에서 PR과 push마다 정적 모드를 돌려 검사가 실패하면 job을 실패로 처리합니다.
