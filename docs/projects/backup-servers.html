보안 사례 #06

서버 7대 통합과 여러 겹의 백업 설계

노후 서버 7대를 Hyper-V로 합치며 외부에서 바로 들어오던 원격 접속을 없애고, 스냅샷 하나에 기대던 복구를 여러 겹의 백업으로 바꿨습니다.

기간
2023.04–2025.03
역할
서버 점검, 가상화 재설계와 이관, 백업과 이중화 설계, 절차 문서화
직무
DevOps, 인프라, 보안

경과

  1. 점검서버마다 역할과 외부 노출 상태를 확인했습니다
  2. 통합Windows Server 2022와 Hyper-V로 합쳐 옮겼습니다
  3. 접근 정리인바운드는 기본 차단하고 원격 접속은 내부망 경로로만 열었습니다
  4. 복구 수단 나누기변경 제한 백업, AWS 서버 이미지, MSSQL 복제, 이중화 서버
  5. 문서화담당자가 없어도 따라 할 수 있게 복구 절차를 남겼습니다

배경

사내 서버 7대는 오래된 장비였습니다. 웹 서버와 DB에는 외부에서 바로 원격 접속할 수 있었고, 출결 서버는 Windows XP 기반이었습니다. 장애가 나면 기댈 수 있는 것은 Hyper-V 스냅샷 하나였고, 담당자가 없을 때도 복구할 수 있는 절차가 필요했습니다.

발견

서버마다 역할과 외부 노출 상태를 하나씩 점검하면서 알았습니다.

조치

  • 서버를 Windows Server 2022와 Hyper-V 환경으로 통합하고 이관했습니다.
  • 방화벽은 인바운드를 기본 차단하고 아웃바운드는 필요한 것만 허용하게 다시 짰고, 웹 서버와 DB에 외부에서 바로 들어오던 원격 접속을 없앴습니다.
  • 복구 수단을 별도 볼륨에 쓰기를 제한한 백업, AWS 서버 이미지, MSSQL 복제, API가 실패하면 이중화 서버로 넘기는 흐름으로 나눴습니다.
  • 백업 접근은 사내 게이트웨이 IP 중심으로 제한하고 복구 절차를 문서로 남겼습니다.
  • Windows XP 기반 출결 서버를 새로 개발해 IIS에 올리고 인트라넷 DB와 연동했습니다.

부딪힌 문제

  1. 웹 서버와 DB에 외부에서 바로 원격 접속

    해결방화벽 재설계와 내부망 경로

    결과외부 원격 접속 경로를 없앰

  2. Hyper-V 스냅샷 하나에 기대던 복구

    해결별도 볼륨 백업, AWS 이미지, MSSQL 복제

    결과복구 수단을 여러 겹으로 나눔

  3. 백업 이미지를 올리는 일에 대한 팀원 반발

    해결그 이미지로 테스트 서버를 띄우는 쓰임을 함께 보여 줌

    결과절차 문서로 손을 덜어 줌

재발 방지와 협업

사내 PC 이미지를 주기적으로 백업 시스템에 올리는 일에는 번거롭다는 팀원들의 반발이 있었습니다. 백업이 왜 필요한지 설명하고, 그 이미지로 테스트 서버를 띄우면 테스트가 빨라진다는 점을 함께 보여 줬습니다. 절차는 문서로 정리해 손이 덜 가게 했습니다.
