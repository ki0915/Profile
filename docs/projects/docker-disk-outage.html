CASE-07운영 사례2023.04–2025.03

5성급 호텔 서버의 디스크 고갈 장애와 재발 방지

배포 때마다 쌓인 Docker 이미지와 중지된 컨테이너가 디스크를 채워 서비스가 멈춘 장애를 복구하고, 주기 정리를 자동화해 같은 원인의 장애를 막았습니다.

역할
장애 원인 확인, 정리와 자동화, 운영 문서 작성
직무
DevOps, 인프라

대응 흐름

  1. 01장애 확인서비스가 멈춰 디스크가 가득 찬 것을 확인했습니다
  2. 02원인 찾기배포마다 남은 이미지와 중지된 컨테이너를 찾았습니다
  3. 03복구쓰지 않는 이미지와 컨테이너를 지우고 서비스를 다시 올렸습니다
  4. 04자동화같은 정리를 cron으로 주기 실행했습니다
  5. 05재현과 가드퇴사 뒤 개인 랩에서 장애를 재현하고 단계적 정리 가드를 만들었습니다

해결한 문제

  1. 문제

    배포마다 쌓이는 Docker 이미지

    쓴 것

    cron 주기 정리

    효과

    같은 원인의 서비스 중단이 다시 없었음

  2. 문제

    롤백용 이미지까지 지울 위험

    쓴 것

    디스크 사용률에 따라 단계적으로 정리하는 가드

    효과

    재현 실험의 배포가 모두 성공

전과 후

디스크 정리

+결과cron으로 주기 실행

재현 실험의 배포

−전14회 중 7회 실패

+후14회 모두 성공

배경

상황

5성급 호텔 고객사의 서버는 Ubuntu 위에서 Docker 컨테이너로 서비스를 돌렸습니다. 관리자 페이지와 DB, 서버 상태는 SSL VPN으로 접속해 점검했습니다. Grafana와 Prometheus 지표가 임계치에 가까워지면 미리 조치해 왔습니다.

어떻게 알았나

서비스가 멈춰 확인해 보니 서버 디스크가 가득 차 있었습니다. 배포 때마다 남은 미사용 Docker 이미지와 중지된 컨테이너가 원인이었습니다.

내가 한 것

  • 중지된 컨테이너와 쓰지 않는 이미지를 지워 공간을 확보하고 서비스를 다시 올렸습니다.
  • 같은 정리 작업을 cron에 등록해 사람이 챙기지 않아도 주기적으로 돌게 했습니다.
  • 로그와 Docker 이미지 정리 절차, 서버 점검 표준을 문서로 남겼습니다.
  • 퇴사 뒤에는 이 장애를 작은 디스크로 재현해, 롤백용 이미지는 지키면서 디스크 사용률에 따라 단계적으로 정리하는 가드를 개인 랩에서 다시 만들었습니다.

갖춘 것

  • seccheck

    KISA 주요정보통신기반시설 기준의 Unix 계정과 권한 점검 10개 항목, 모니터링 2개 항목을 점검합니다. 지난달 결과와 비교해 신규, 미조치와 경과일, 조치 완료 항목을 나눕니다.

    단위 테스트로 검증했습니다.
  • disk-guard

    디스크 사용률 단계에 따라 Docker 이미지, 빌드 캐시, 중지 컨테이너를 정리하되, 롤백용 최신 이미지와 사용 중인 이미지는 남깁니다.

    1GiB 디스크 재현 실험에서 정리 없이 배포하면 14회 중 7회가 실패했지만, 가드를 적용하자 14회 모두 성공했습니다.
  • 안전장치와 기록

    기본은 dry-run으로 실행하고 flock으로 동시 실행을 막습니다. JSON 감사 로그와 Prometheus 지표, 경보 규칙을 남깁니다.

쓴 기술

Docker, Ubuntu
고객사 서비스 운영 환경
cron
이미지와 컨테이너 주기 정리
Grafana, Prometheus
CPU, 메모리, 컨테이너 지표 감시

확인과 재발 방지

cron 주기 정리를 건 뒤로는 같은 원인으로 디스크가 차서 서비스가 멈추지 않았습니다. 개인 랩의 재현 실험에서는 정리 없이 배포하면 절반이 실패했고, 가드를 적용하자 모두 성공했습니다.
