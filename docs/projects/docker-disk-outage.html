운영 사례2023.04–2025.03

5성급 호텔 서버의 디스크 고갈 장애와 재발 방지

배포 때마다 쌓인 Docker 이미지와 중지된 컨테이너가 디스크를 채워 서비스가 멈춘 장애를 복구하고, 주기 정리를 자동화해 같은 원인의 장애를 막았습니다.

역할
장애 원인 확인, 정리와 자동화, 운영 문서 작성

상황

5성급 호텔 고객사의 서버는 Ubuntu 위에서 Docker 컨테이너로 서비스를 돌렸습니다. 관리자 페이지와 DB, 서버 상태는 SSL VPN으로 접속해 점검했습니다. Grafana와 Prometheus 지표가 임계치에 가까워지면 미리 조치해 왔습니다.

어떻게 알았나

서비스가 멈춰 확인해 보니 서버 디스크가 가득 차 있었습니다. 배포 때마다 남은 미사용 Docker 이미지와 중지된 컨테이너가 원인이었습니다.

내가 한 것

  • 중지된 컨테이너와 쓰지 않는 이미지를 지워 공간을 확보하고 서비스를 다시 올렸습니다.
  • 같은 정리 작업을 cron에 등록해 사람이 챙기지 않아도 주기적으로 돌게 했습니다.
  • 로그와 Docker 이미지 정리 절차, 서버 점검 표준을 문서로 남겼습니다.
  • 퇴사 뒤에는 이 장애를 작은 디스크로 재현해, 롤백용 이미지는 지키면서 디스크 사용률에 따라 단계적으로 정리하는 가드를 개인 랩에서 다시 만들었습니다.

확인과 재발 방지

cron 주기 정리를 건 뒤로는 같은 원인으로 디스크가 차서 서비스가 멈추지 않았습니다. 개인 랩의 재현 실험에서는 정리 없이 배포하면 절반이 실패했고, 가드를 적용하자 모두 성공했습니다.
