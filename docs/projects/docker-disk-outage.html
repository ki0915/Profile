실무 트러블슈팅

5성급 호텔 서버 디스크 고갈 장애 대응

배포할 때마다 Docker 이미지와 중지된 컨테이너가 쌓여 디스크가 가득 찼고, 서비스가 멈췄습니다. 원인을 확인해 정리한 뒤 cron으로 주기 정리를 자동화했습니다.

고객사 운영 업무라 공개 저장소가 없습니다. 이 장애를 재현한 실험은 보안 운영 랩에 있습니다.

요약

5성급 호텔 고객사 서버에서 배포마다 쌓인 Docker 이미지와 중지된 컨테이너가 디스크를 채워 서비스가 멈췄습니다. 원인을 확인해 정리하고 서비스를 다시 올린 뒤, 같은 정리를 cron으로 자동화했습니다. 정리 절차와 서버 점검 표준은 문서로 남겼습니다.

명세

기간2023.04 – 2025.03 재직 중
역할장애 원인 확인, 정리와 자동화, 운영 문서 작성
환경5성급 호텔 고객사 Ubuntu 서버, SSL VPN 원격 관리
기술Docker, cron, Grafana, Prometheus, Ubuntu, MariaDB
저장소해당 없음 (실무, 소스 비공개)

배경

이 고객사 서버는 Ubuntu 위에서 Docker 컨테이너로 서비스를 돌렸습니다. 관리자 페이지와 DB, 서버 상태는 SSL VPN으로 접속해 점검했고, Grafana와 Prometheus 지표가 임계치에 가까워지면 미리 조치해 왔습니다.

그러다 서비스가 멈췄습니다. 확인해 보니 서버 디스크가 가득 차 있었습니다.

한 일

원인 확인
배포 때마다 남은 미사용 Docker 이미지와 중지된 컨테이너를 원인으로 확인했습니다.
정리와 복구
중지된 컨테이너와 쓰지 않는 이미지를 지워 공간을 확보하고 서비스를 다시 올렸습니다.
자동화
같은 정리 작업을 cron에 등록해, 사람이 챙기지 않아도 주기적으로 돌게 했습니다.
문서화
로그와 Docker 이미지 정리 절차, 서버 점검 표준을 문서로 남겼습니다.

별개 장애: MariaDB 로그 누적

디스크 고갈과는 다른 사건으로, 고객사 운영 중 MariaDB 로그가 쌓여 생긴 장애도 해결했습니다. 지원이 끝난 Ubuntu 18.04 서버는 22.04로 업그레이드했습니다.

결과

  • 정리 작업이 cron으로 주기 실행되면서, 같은 원인으로 디스크가 차서 서비스가 멈추는 일을 막았습니다.
  • 정리 절차와 서버 점검 표준을 문서로 남겨 점검 순서를 맞췄습니다.

퇴사 뒤 다시 해 본 것

퇴사 뒤 이 장애를 1GiB 디스크로 재현해, 롤백용 이미지는 지키면서 디스크 사용률에 따라 단계적으로 정리하는 방식으로 다시 만들어 봤습니다. 결과는 보안 운영 랩에 정리했습니다.

디스크 용량, 정리 전후 사용률, cron 실행 주기는 기록이 남아 있지 않아 숫자로 적지 않았습니다.
