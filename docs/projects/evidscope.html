도구 사례2026.09–2026.10

EvidScope, AI 행동을 감사할 수 있게 근거를 묶는 파일럿

AI가 한 행동과 그때의 권한, 정책, 근거 문서, 사람의 판단을 서명 원장으로 이어 붙여 감사 담당자가 대조할 수 있게 한 로컬 파일럿입니다.

역할
문제 정의와 우선순위, 모델과 비용 조건 결정, 최종 검토 (설계와 구현은 AI와 협업)

풀려던 문제

기업이 업무에 AI를 쓰면 결과 보고는 받지만, AI가 어떤 도구를 어떤 권한으로 불렀고 어떤 근거를 봤는지는 확인하기 어렵습니다. 감사 담당자는 AI의 행동과 도구 결과, 당시 권한과 정책 버전, 원본 문서를 대조하고 판단을 남길 수 있어야 합니다. AI 활동이 보여야 AI 거버넌스를 시작할 수 있다고 보고 기획했습니다.

문제를 확인한 방법

합성 부하 시험을 돌리자 요청마다 서명 원장 전체를 다시 검증하느라 접수가 밀렸습니다.

실제 HTTP 요청으로 권한을 검토하다가, 읽기 권한만 있어야 할 감사자가 거버넌스 시스템과 평가, 과제를 바꿀 수 있는 결함을 찾았습니다.

고른 설계와 이유

감사 담당자가 근거를 확인하고 판단을 남기는 도구로 범위를 정했고, AI 실행을 막는 기능은 넣지 않았습니다. 근거가 없는 항목까지 준수로 세면 실제 상태가 가려지므로, 근거 부족과 미평가는 준수로 세지 않게 했습니다.

직접 설계하고 만든 것

  • 문제 정의와 우선순위, 사용할 모델과 비용 조건을 정했고, 설계와 구현, 감사 작업은 AI와 나눠 맡았습니다.
  • 시스템을 수집, 감사 화면, 저장, 분석의 네 프로세스로 나누고, 최종 인증과 서명 원장은 저장 프로세스만 갖게 했습니다.
  • 원장 재검증 병목은 이미 검증한 지점 이후의 변경분만 검증하도록 바꾸고, 변조를 찾으면 멈추는 원칙은 유지했습니다.
  • 감사자 권한 결함은 공통 권한 경계에서 reviewer나 admin 역할을 요구하도록 고쳤습니다.
  • 한국 인공지능 기본법의 의무를 요구사항으로 옮기고, 법 적용과 충분성 판단은 사람이 내리게 했습니다.

검증 방법

같은 합성 시나리오로 수정 전후의 부하 시험 결과를 비교했습니다. 권한 결함은 권한 없는 변경 요청 30건이 모두 거부되고 서명 상태가 바뀌지 않는 것을 회귀 시험으로 고정했습니다.

시연

만든 방법

  1. ingress 프로세스앱과 보안 도구에서 보내는 데이터를 받아 본문 속성을 지우고, 허용된 메타데이터만 증거로 넘깁니다.
  2. vault 프로세스최종 인증을 처리하고 서명 원장을 소유합니다.
  3. worker 프로세스claim, lease, version 방식으로 작업을 가져가 상시 LLM 없이 규칙으로 분석합니다. 증거나 정책 버전이 바뀌면 이전 결과를 최신으로 확정하지 않습니다.
  4. audit 프로세스감사 담당자가 근거를 확인하고 판단을 남기는 단계로, 사람이 쓰는 검토 화면은 분석 경로와 분리했습니다.
