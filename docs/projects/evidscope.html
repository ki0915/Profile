EvidScope

AI가 한 일과 그 근거를 사람이 검토하게 돕는 감사 증거 파일럿

AI 행동, 도구 결과, 당시 권한과 정책 버전, 원본 문서, 사람의 판단을 서명 원장으로 이어 붙여, 감사하는 사람이 서로 대조할 수 있게 한 로컬 파일럿입니다.

저장소 github.com/ki0915/EvidScope

요약

실행 로그만으로는 AI가 실제로 무엇을 했고, 그때 권한이 있었는지, 어떤 근거를 검토했는지 설명하기 어렵습니다. EvidScope는 행동과 근거를 서명 원장으로 이어 붙이고, 확인하지 못한 사실은 unknown으로 남겨 "등록됨"과 "확인됨"을 섞지 않습니다. 실행을 승인하거나 차단하는 엔진이 아니라, 내부감사나 보안 운영 담당자가 근거를 확인하고 판단을 기록하는 도구입니다. 문제와 조건은 제가 정했고 설계와 구현은 AI와 함께 했습니다.

목적

AI에게 일을 맡기면 결과 보고는 받지만, 실제로 어떤 도구를 어떤 권한으로 불렀는지는 확인하기 어렵습니다. 감사하는 사람은 AI의 행동과 도구 결과, 당시 권한과 정책 버전, 원본 문서를 대조할 수 있어야 하고, 사람이 내린 판단도 기록으로 남아야 합니다.

숫자도 문제였습니다. 근거가 없는 항목까지 준수로 세면 숫자는 좋아 보이지만 실제 상태를 가립니다. 그래서 등록된 AI 자산, 실제로 받은 기록, 증거 커버리지를 따로 셉니다.

만든 기능

역할을 나눈 네 프로세스

수집(ingress), 감사 화면(audit), 저장(vault), 분석(worker)으로 나눴습니다. 최종 인증과 원장은 vault만 갖고, worker는 claim과 lease, version 방식으로 분석합니다. 출처는 HMAC과 nonce로 인증하고, 원장은 Ed25519로 서명하며, 내보낸 증적은 별도 공개키와 checkpoint, hash로 독립 검증합니다.

문서가 있다는 것과 근거가 충분하다는 것을 구분

근거 문서는 원본 파일(최대 4MiB)을 암호화해 보관하고 hash, 복구 가능성, 모델, 목적, 정책 버전을 함께 대조합니다. 문서가 손상되거나 버전이 바뀌면 재검토로 돌리고, 근거가 부족한 보완 과제는 사람이 충족이라고 입력해도 종결하지 않습니다.

요구사항과 운영 기능

요구사항 31개(한국 18개)와 기술 검사 23종을 다루고, 적용 후보와 사람의 최종 판단을 구분합니다. OIDC 세션 회수, tenant 격리, 암호화 백업과 새 경로 복구를 넣었고, 보고서는 서명으로 고정합니다.

해결한 문제와 결과

원장 재검증 병목

요청마다 테넌트의 서명 원장 전체를 다시 검증해서 부하가 걸리면 접수가 밀렸습니다. 트랜잭션의 checkpoint를 묶고, 이미 검증한 지점 이후의 서명 구간과 조회 사본 변경분만 검증하게 바꿨습니다. 변조를 찾으면 멈추는(fail-closed) 원칙은 유지했고, 전체 내보내기와 무결성 점검, 백업은 여전히 전체를 검증합니다.

감사자가 판정을 바꿀 수 있던 권한 결함

실제 HTTP 검토에서 읽기 권한만 있어야 할 감사자가 거버넌스 시스템과 평가, 과제를 바꿀 수 있는 결함을 찾았습니다. vault의 공통 권한 경계에서 reviewer나 admin을 요구하게 고쳤고, gateway와 vault 직접 요청 30건이 거부되고 서명 상태가 바뀌지 않는 것을 회귀 시험으로 고정했습니다.

의의

AI가 한 일을 "기록이 있다"에서 "근거로 확인했다"까지 단계로 나눠 보여 주는 구조를 만들었습니다. 무결성 검증을 느슨하게 하지 않고도 처리 병목을 풀었고, 실패한 시험도 지우지 않고 원본 로그로 남겼습니다.

다음 단계

  • 실제 조직 IdP와 외부 SIEM, 정책과 업무 결과 연동
  • 원격 KMS와 WORM 저장소, 이중화 검증과 실제 복구 목표(RPO, RTO) 측정
  • 같은 감사 과제에서 근거를 찾는 시간과 누락 발견을 비교 측정

무엇을 풀지, 무엇을 먼저 할지, 모델과 비용 조건은 제가 정했고 설계와 구현은 AI와 함께 했습니다. 로컬 파일럿이며 법률 준수 인증과 실제 금융기관 연동은 하지 않았습니다. 고객 성과나 상용 제품 대비 우위로 제시할 측정값은 없습니다.
