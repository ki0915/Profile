EvidScope

AI 에이전트의 위험 행동을 판정 모델로 가려내 감사 증거로 남기는 보안 도구

소개

Claude Code와 Codex가 실행하는 도구 호출을 실시간으로 받아 규칙과 직접 학습한 판정 모델로 위험한 행동을 가려내고, 당시 권한과 정책, 사람의 판단과 함께 서명 원장에 남겨 감사 증거로 쓰게 하는 도구입니다.

기업이 AI를 쓰면 실행 로그만으로는 AI가 어떤 권한과 근거로 판단했는지 설명하기 어렵고, 원본 증거를 확보해 책임추적성을 부여하기도 어렵습니다. 이런 상황에서 AI 활동 가시성과 감사 거버넌스를 지원하는 보안 도구를 만들었습니다.

처리 흐름

  1. 규칙 위험 규칙 67개와 행동 순서 규칙이 먼저 경보를 냅니다
  2. JEV-9B 모든 세션의 위반 여부를 확률과 함께 판정하고, 애매하면 보류합니다
  3. Qwen3-4B 위반이나 보류로 본 세션만 다시 받아 증거 행동과 위험 유형을 짚습니다
  4. 서명된 대응표 모델이 아니라 대응표가 인공지능 기본법, ISMS-P, EU AI Act 항목을 계산합니다
  5. 서명 원장 당시 권한과 정책, 사람의 판단과 함께 남겨 감사 증거로 씁니다

구현

판정 파이프라인을 규칙, 1차 판정 모델, 2차 판정 모델, 서명된 대응표의 네 단계로 나눴습니다. 위험 규칙 67개와 행동 순서 규칙이 먼저 경보를 내고, JEV-9B가 모든 세션의 위반 여부를 확률과 함께 판정합니다. JEV-9B가 위반이나 보류로 본 세션과 규칙 경보를 정상으로 본 세션만 Qwen3-4B가 다시 받아 증거가 된 행동과 위험 유형을 짚습니다. 법 조항은 모델이 쓰지 않고 서명된 대응표가 계산합니다.

판정이 흔들리지 않도록 모델은 규칙 경보를 지울 수 없게 했고, 경보를 낮추려면 두 모델이 모두 동의해야 하며, 보안 기능 해제나 기록 변조 같은 보호 경보는 낮추지 못하게 했습니다.

  • JEV-9B는 Qwen3.5-9B 위에 판정 블록을 얹은 모델로, 글을 생성하지 않고 예와 아니오를 확률과 함께 한 번에 냅니다. 확률로 판단을 보류할 수 있어서 모든 세션의 1차 판정을 맡겼습니다.
  • Qwen3-4B는 규칙 소견이 없는 세션에서도 어느 행동이 증거인지 짚어 내서, 1차 판정에서 걸린 세션의 근거 행동과 위험 유형을 맡겼습니다.
  • 두 모델은 같은 학습 데이터로 4비트 QLoRA 학습을 했고, 보류 문턱은 시험과 같은 분포의 검증 분할에서만 골랐습니다.
  • 공개 데이터는 ASSEBench를 학습과 평가에 쓰고, R-Judge와 ATBench는 외부 시험으로만 남겼습니다. 외부 시험과 겹치는 공개 기록은 학습 데이터에서 기계적으로 뺐습니다.
  • 모든 라벨 세션은 프롬프트 없는 한 레코드 형식으로 모아, 판정 모델을 바꿔도 같은 데이터와 채점기로 학습하고 비교하게 했습니다.
  • Claude Code 실행 전 hook에서는 감사 설정 변경, 보안 기능 끄기, 비밀을 읽어 바로 외부로 보내는 명령만 막고 막은 사실을 원장에 남깁니다.
  • 한국 인공지능 기본법 제30~36조와 제40조의 의무를 요구사항 18개로 정리하고, 경보를 ISMS-P와 EU AI Act 항목까지 서명된 대응표로 연결했습니다.
