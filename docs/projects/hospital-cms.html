보안 사례2023.04–2025.03

대형병원 키오스크 CMS의 권한 결함 수정과 보안점검 대응

대형병원 키오스크를 원격으로 관리하는 CMS를 혼자 만들어 운영했고, 세션 검증보다 권한 부여가 먼저 일어나던 결함을 고쳐 병원 보안점검을 통과했습니다.

역할
CMS 단독 설계, 개발, 운영과 보안점검 대응

상황

고객은 4만 평 규모의 대형병원이었습니다. 병원 내부망의 키오스크 약 200대는 장애가 날 때마다 담당자가 현장으로 가야 했습니다. 이 부담을 줄이려고 원격 관리 CMS를 혼자 만들어 운영했습니다. CMS에는 화면 미러링과 원격 명령, 예약 배포를 넣었습니다.

납품하는 CMS는 병원 보안점검을 통과해야 했고, 권한 분리와 계정 정책을 병원 기준에 맞춰야 했습니다.

어떻게 알았나

병원 보안 요구에 맞춰 인증과 권한 구조를 고치던 중에, Redis에서 세션 검증이 끝나기 전에 임시 권한이 먼저 붙는 구간을 찾았습니다. 요청 타이밍에 따라 검증되지 않은 세션이 권한을 쥘 수 있는 구조였습니다.

내가 한 것

  • 권한 부여를 세션 검증 뒤로 옮겨 처리 순서를 바로잡았습니다.
  • 서버 개인키로 서명하는 JWT 인증과 bcrypt 비밀번호 해시, 관리자와 운영자 역할을 나눈 RBAC를 구현했습니다.
  • 90일마다 비밀번호를 바꾸게 하고, 로그인 실패 횟수 제한과 재사용 금지, 계정 잠금 정책을 적용했습니다.
  • ORM으로 쿼리를 만들어 SQL을 직접 조립하는 곳을 줄였습니다.
  • 연동 문제는 브라우저 개발자 도구의 Network 탭에서 엔드포인트와 요청 내용, Authorization 헤더의 JWT를 확인하며 분석했습니다.

확인과 재발 방지

납품한 CMS 전체가 병원 보안점검을 통과했습니다.
