FIELD WORK

실무에서 해결한 문제

미디어솔루션 · 연구개발팀 · 2023.04–2025.03. 기존 실무 프로젝트는 유지하되 고객사 명칭은 공개 화면에서 익명화했습니다.

01

INCIDENT RESPONSE · IIS

고객 CMS 침해대응과 실행 경로 분석

KISA 통보로 확인된 침해사고에서 현장 시스템 접근과 관리자 계정을 복구하고, 로그와 IIS 응용프로그램 풀에서 실행되는 악성 행위를 추적했습니다. 구형 미들웨어·웹 필터의 취약 구성을 점검하고 VPN 도입, 프레임워크 개선과 AWS 이관 권고안을 정리했습니다.

결과서비스 접근을 복구한 뒤 악성 실행 경로와 재발 방지를 위한 기술 조치·이관 선택지를 고객에게 전달했습니다.
02

INCIDENT RESPONSE · AWS

크립토재커 침해대응과 클라우드 재구축

서비스 중단, 높은 CPU·메모리 점유, 공격자가 설치한 가상화 환경을 조사하고 구형 ASP.NET 구성의 위험을 공개 CVE와 대조했습니다. MSSQL 데이터를 격리 환경에서 확인한 뒤 애플리케이션을 EC2, 데이터베이스를 RDS로 재구축하고 보안그룹을 운영 IP 허용목록 중심으로 조정해 RDP 접근을 차단했습니다.

결과두 사고 중 기록된 한 건은 인지부터 복구까지 4일. AWS 이관 후 재직 중 관측 범위에서 동일 원인 공격 재발 없음.

03

FULL-STACK · OPERATIONS

병원 키오스크 통합 CMS

약 200대 단말의 현장 방문을 줄이기 위해 TypeScript·Angular·Node.js·MariaDB·Redis로 관리 시스템을 단독 설계·개발·운영했습니다. WebSocket 원격 화면과 명령, 예약·그룹 배포, 중단점 롤백, 전원 스케줄링을 구현했습니다.

결과원격 조치와 배포 흐름을 운영에 적용하고, 인증·RBAC·계정 정책을 포함한 납품 CMS가 병원 보안점검을 통과했습니다.
04

BACKUP · RECOVERY

백업·이중화 체계

Hyper-V 스냅샷 의존을 줄이기 위해 별도 볼륨의 변경 제한 백업, AWS 서버 이미지·MSSQL 복제, API 실패 시 전환 흐름, 게이트웨이 IP 접근 제한과 복구 절차를 구성했습니다.

결과퇴사 후 2025년 4월 발생한 랜섬웨어 복구에 사전 구축한 체계가 사용됐고, 전달받은 기록상 데이터 손실 없이 1일 내 복구됐습니다.
05

WINDOWS SERVER · HYPER-V

노후 서버 통합과 접근 경로 개선

노후 서버 7대의 역할과 외부 노출을 확인하고 Windows Server 2022·Hyper-V 기반으로 통합·이관했습니다. 웹·DB 서버의 직접 원격 접근을 없애고 내부망 경로로 제한했으며 XP 기반 출퇴근 서버도 교체했습니다.

결과분산된 서버 역할과 관리 경로를 정리해 유지보수 기준과 접근통제를 함께 개선했습니다.
06

SEGMENTED NETWORK · AUTH

분리망 본인인증 연동

외부 통신이 제한된 환경에서 NICE CPClient와 Electron, IIS/.NET 로컬 인증 서버를 연결했습니다. 인증 통신 경로를 제한하고 처리 이력과 복구 절차를 중앙에서 확인할 수 있도록 구성했습니다.

결과제한된 네트워크 조건에서도 본인인증을 운영할 수 있는 연동 구조와 장애 대응 문서를 남겼습니다.

HOW I WORK
